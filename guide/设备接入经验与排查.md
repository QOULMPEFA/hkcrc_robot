# 设备接入经验与排查（Thor / 2026-08-31）

本文记录 Thor 平台 4 个硬件设备接入踩过的坑与结论，供后续 AI Agent / 维护者快速定位。适用平台：Jetson Thor（Ubuntu 24.04 aarch64，kernel `6.8.12-tegra`，系统 Python 3.12，workspace `/home/hkcrc1/robot_code`）。

## 1. USB 设备"能枚举 ≠ 有驱动 ≠ 能访问"三层检查

排查任何 USB 外设，按顺序查：

1. **枚举**：`lsusb` 能看到 VID:PID —— 只代表 USB 协议层认出硬件。
2. **驱动绑定**：`ls -l /dev/ttyUSB* /dev/ttyACM*` 看有没有生成设备节点。生成节点依赖内核驱动模块，缺驱动时 `lsusb` 照常显示但没有节点（CH340 就是这种情况）。
3. **权限**：节点属主可能是 `root:dialout`，用户需在 `dialout` 组（`usermod -aG dialout <user>`）或临时 `chmod 666`。

对照表（本机常见设备）：

| 设备 | VID:PID | 类型 | 节点 |
|---|---|---|---|
| ZQWL USB-CAN-FD | `3562:0101` | CDC-ACM 串口 | `/dev/ttyACM0` |
| CH340 (WCH) | `1a86:7523/5512/7524` | USB 串口 | `/dev/ttyUSB0` |
| RealSense 455 | `8086:0b5c` | 相机 | /dev/video* |
| "hawk" 摄像头 | `2207:0019` (Rockchip) | 厂商专用 | 无标准节点 |

## 2. Thor 内核缺 ch341 驱动 —— 现场编译 ch341.ko

**现象**：CH340 插上 `lsusb` 可见 `1a86:7523`，但无 `/dev/ttyUSB*`，gimbal_sdk 报"发现 N 个串口设备但均未匹配 CH340"。

**根因**：Thor 内核 `/lib/modules/6.8.12-tegra/kernel/drivers/usb/serial/` 只有 `cp210x/ftdi_sio/option/usb_wwan/garmin_gps`，**没有 ch341/ch34x**。

**解决**（Thor 已具备 `linux-headers-6.8.12-tegra` + gcc + make + 联网）：
```bash
mkdir -p ~/ch341_build && cd ~/ch341_build
curl -O https://raw.githubusercontent.com/torvalds/linux/v6.8/drivers/usb/serial/ch341.c
# Makefile:  obj-m := ch341.o / KDIR := /lib/modules/$(uname -r)/build
make
echo ' ' | sudo -S cp ch341.ko /lib/modules/$(uname -r)/kernel/drivers/usb/serial/
echo ' ' | sudo -S depmod -a && echo ' ' | sudo -S modprobe ch341
# 之后 /dev/ttyUSB0 出现，重启自动加载（depmod 已生成别名）
```
- 源码用与内核同小版本（v6.8）的主线 `ch341.c`，兼容性最好。
- 编译器版本与构建内核不同只出 warning，不影响该串口驱动。
- **⚠️ 内核升级后需重编译**。配方备份在 `scripts/ch341_build/`。

## 3. ZQWL USB-CAN-FD 适配器 —— 它是串口，不是 ZLG VCI

- 设备 `3562:0101` 是 **CDC-ACM 串口**（/dev/ttyACM0），走 libusb 的 ZLG VCI 通道（libusbcanfd.so）**不适用**。
- BrainCo bc-stark-sdk 对它有原生串口路径：`sdk.init_zqwl_canfd(port, arb_baudrate, data_baudrate)` —— **同步函数、返回 None**，之后 `sdk.init_device_handler(sdk.StarkProtocolType.CanFd, master_id)` 才返回可 `await` 的设备句柄。
- 版本锁 **bc-stark-sdk 2.0.2**（Thor 曾装 2.0.3，API 不同）。
- CANFD 参数（实测工作）：arb **1M** / data **5M**、扩展帧、BRS。
- 灵巧手 Revo1 slave `0x7F`，Revo2 默认 `0x7E`。
- **为何要用它**：系统 can0 是 500k 经典 CAN（UGV+升降台），CANFD 不能混在经典 500k 总线上，ZQWL 提供独立 CANFD 总线。

## 4. UR5e —— 以太网口被 DHCP 卡死

**现象**：`enP2p1s0` 链路 UP（网线插着、LOWER_UP）但只有 IPv6 link-local，无 IPv4，arm 模块连 `192.168.56.101` 一直失败。

**根因**：NetworkManager 用默认 `Wired connection 1`（DHCP）接管该口，但 UR 网络**没有 DHCP 服务器**（UR 出厂静态 `192.168.56.101`），永远拿不到地址。

**排查口诀**：链路 UP ≠ 有 IP；先 `ip -br addr` 看接口，再 `ip addr add` 临时配同一网段 ping 探测，确认后再持久化。

**解决**：
```bash
sudo nmcli con add type ethernet ifname enP2p1s0 con-name ur-net \
  ipv4.method manual ipv4.addresses 192.168.56.10/24 ipv6.method ignore
sudo nmcli con up ur-net
```
- 新建 profile 的 autoconnect 优先级 0 > 自动生成 DHCP 配置的 -999，重启不冲突。
- UR 三端口：**29999**（Dashboard）/ **30001**（URScript 主）/ **30002**（Secondary 状态）。
- 验证：`ping 192.168.56.101` → arm 日志 `[Arm] Connected to UR5e`。

## 5. RealSense 设备节点（455）

- `/dev/video4` = 彩色（yuyv422），`/dev/video0` = 深度（gray16le）。camera 配置用显式 `sources` 而非 `auto_detect`。

## 6. Quest 视频桥 token
