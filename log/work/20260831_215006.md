## 四个问题的修复（全部已实测验证）

### 1. 灵巧手（ZQWL USB-CAN-FD 适配器）
- 用户把灵巧手经 **ZQWL USB-CAN-FD**（USB `3562:0101`，**CDC-ACM 串口** `/dev/ttyACM0`，非 ZLG VCI 设备）接到 Thor
- CANFD 参数：arb 1M / data 5M、扩展帧；Revo1 手 slave `0x7F`（Revo2 默认 0x7E）
- `hand.py` 新增 `zqwl_canfd` 协议：`_LIBSTARK.init_zqwl_canfd(port, 1M, 5M)`（**同步、返回 None**）→ `init_device_handler(CanFd, master)`；server.py active config 改为 `"hand": {"protocol": "zqwl_canfd", "port": "/dev/ttyACM0", "slave_id": 0x7F}`
- bc_stark_sdk 版本锁 **2.0.2**（2.0.3 的 API 不同）；hkcrc1 加入 `dialout` 组
- ✅ 日志 `[Hand] connected=True`，实时 position/current 上报，用户确认"灵巧手可以控制了"

### 2. RealSense（深度图修复）
- 之前已修：server.py camera 显式 `sources: /dev/video4`（彩色 yuyv422，720p）；config 里补注 `/dev/video0` 深度 gray16le
- ✅ 正常出彩色画面

### 3. 云台（CH340 驱动缺失 → 现场编译 ch341.ko）
- **根因**：Thor 内核 `6.8.12-tegra` 没有 ch341/ch34x 模块（`/lib/modules/.../usb/serial/` 只有 cp210x/ftdi_sio/option/usb_wwan/garmin_gps）。CH340(1a86:7523) 插上 `lsusb` 可见但无驱动绑定 → 无 `/dev/ttyUSB*`
- 排查中先发现的 `2207:0019 "hawk"(manifold)` 设备是**摄像头**（用户确认，稍后调试），不是云台驱动
- **修复**：Thor 有 `linux-headers-6.8.12-tegra` + gcc + make + 联网 → 下载 Linux **v6.8** 主线 `drivers/usb/serial/ch341.c`，`make` 编出 `ch341.ko`，装到 `/lib/modules/6.8.12-tegra/kernel/drivers/usb/serial/` + `depmod -a` + `modprobe ch341`
- ✅ 日志：`匹配到目标端口 /dev/ttyUSB0 → USB VID:PID=1A86:7523`、`串口初始化成功`、`[Gimbal] Reconnected — yaw=-3.6°, pitch=0.3°`
- ⚠️ **内核升级需重编译该模块**（源码在 Thor `/home/hkcrc1/ch341_build/`）

### 4. UR5e 机械臂（以太网口卡 DHCP）
- **根因**：UR 接 Thor 以太网口 `enP2p1s0`，但该口被 NetworkManager 以 DHCP 接管（`Wired connection 1`），UR 网络无 DHCP 服务器（UR 静态 192.168.56.101）→ 一直拿不到 IPv4 → arm 连不上
- **修复**：新建 NM 连接 `ur-net`（enP2p1s0 → manual `192.168.56.10/24`，autoconnect 优先 0 > 旧 DHCP 的 -999，重启不冲突）
- ✅ 日志：`State reader connected to port 30002`、`[Arm] Connected to UR5e (192.168.56.101)`、`set_payload(0.5kg)`；三端口 29999/30001/30002 全 OPEN
