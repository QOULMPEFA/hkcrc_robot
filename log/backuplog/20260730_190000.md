# v1.21 — Hand Module Fixes

**Date:** 2026-07-30 19:00
**Tags:** v1.21

## Summary

Three critical fixes for the BrainCo dexterous hand (灵巧手) control module:

### Fix 1 — Hand Enable/Disable UI
- Added "使能" (Enable) and "断开使能" (Disable) buttons to hand panel HTML
- Added `hand.enable` / `hand.disable` action bindings for role-based permissions
- Added i18n translations (zh/en) for button labels
- Registered `hand_enable` / `hand_disable` SocketIO handlers in `hand.py`

### Fix 2 — Finger Position Commands Clamped to HW-Native Limits (Root Cause)
- **Problem:** `_handle_cmd` clamped position targets (0-1000 normalized) to hardware-native finger limits (e.g., thumb max=60). Sending "close" (1000) → clamped to `min(60, 1000) = 60`, which is only 6% — the exact position fingers were already at.
- **Root cause:** `_read_finger_limits()` reads `get_all_finger_settings()` which returns native hardware units (0-60, 0-90, 0-81), not the Normalized 0-1000 range. The `FingerUnitMode.Normalized` mode tells the SDK to handle the 0-1000 → native mapping internally.
- **Fix:** Removed hardware-native limit clamping in `_handle_cmd`. Position targets now directly use 0-1000 range, letting the SDK's Normalized mode handle the conversion.

### Fix 3 — Slider Range Restricted to HW-Native Limits
- **Problem:** `_updateHandState` was overriding slider max to `finger_limit.max / 1000` (e.g., 60/1000 = 0.06 = 6%).
- **Fix:** Removed the slider range override. Sliders stay at 0-1 (0%-100%).
