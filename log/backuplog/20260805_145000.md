**Windows 用户：**
按 `Win + R`，输入 `powershell`，回车。

**Mac 用户：**

```
ssh orangepi@192.168.12.1
```

```
orangepi
```

```bash
echo orangepi | sudo -S systemctl restart robot_control_panel
```

等待约 10 秒后刷新浏览器页面 `http://192.168.12.1:6080`。

拔掉机器人电源，等 5 秒，重新插电。等待约 30~60 秒后，浏览器刷新页面即可。

# Orange Pi 部署指南

## 环境概览

| 项目 | 值 |
|------|-----|
| 硬件 | Orange Pi Zero 2W (AArch64) |
| OS | Orange Pi 1.0.4 Noble (Ubuntu 24.04) |
| Python | 3.12.3（系统预装，无 pip） |
| 工作目录 | `/home/orangepi/` |
| 源码目录 | `pr_mini/` |
| 加密产物 | `robot_encrypted/` |
| 服务端口 | 6080 |
| 日志文件 | `/var/log/robot_control_panel.log` |

## 第一步：准备系统环境

### 1.1 安装 pip

系统 Python 不带 pip，需手动安装：

```bash
curl -s https://bootstrap.pypa.io/get-pip.py -o /tmp/get-pip.py
python3 /tmp/get-pip.py --break-system-packages
```

安装后 pip 在 `~/.local/bin/`，使用时加 PATH 或通过 `python3 -m pip` 调用。

> **注意**：Orange Pi 官方系统启用了 PEP 668，所有 pip install 必须加 `--break-system-packages`。

### 1.2 安装 ffmpeg（摄像头推流必需）

```bash
echo orangepi | sudo -S apt-get update
echo orangepi | sudo -S apt-get install -y ffmpeg
```

### 1.3 安装 Python 依赖

```bash
export PATH="$HOME/.local/bin:$PATH"
python3 -m pip install --break-system-packages \
  flask \
  flask-socketio \
  python-can
```

### 1.4 安装 PyArmor（代码加密）

从 PC 下载对应架构的 wheel，上传到香橙派后离线安装：

```bash
# PC 上：
pip download pyarmor==9.2.5 --platform manylinux2014_aarch64 --python-version 312 --only-binary=:all -d ./wheels
# 上传 wheels/ 到香橙派 /tmp/wheels/

# 香橙派上：
python3 -m pip install --break-system-packages /tmp/wheels/*.whl
```

通过局域网 SCP 上传整个 `robot_control/` 到 `/home/orangepi/pr_mini/robot_control/`，同时上传本地 SDK 包：

## 第三步：运行 PyArmor 加密

```bash
cd /home/orangepi/pr_mini
rm -rf /home/orangepi/robot_encrypted
pyarmor gen --output /home/orangepi/robot_encrypted robot_control
```

加密后产物在 `/home/orangepi/robot_encrypted/`，包含：
- `pyarmor_runtime_000000/pyarmor_runtime.so` — AArch64 运行时
- `robot_control/*.py` — 混淆后的 .py 文件
- `robot_control/web_gui/*.py` — 混淆后的 Web GUI

### 复制明文资源

模板和静态文件不需要加密，直接复制：

```bash
cp -r /home/orangepi/pr_mini/robot_control/web_gui/templates \
      /home/orangepi/robot_encrypted/robot_control/web_gui/
cp -r /home/orangepi/pr_mini/robot_control/web_gui/static \
      /home/orangepi/robot_encrypted/robot_control/web_gui/
```

### 上传启动器

`run_server.py` 是明文启动脚本（不参与加密），放在加密目录根下：

```bash
cp /home/orangepi/pr_mini/run_server.py /home/orangepi/robot_encrypted/run_server.py
```

### 复制 SDK 到加密目录

SDK 路径相对于加密后的模块，需放在 `robot_encrypted/` 下：

```bash
cp -r /home/orangepi/pr_mini/motor_sdk /home/orangepi/robot_encrypted/motor_sdk
cp -r /home/orangepi/pr_mini/stepper_motor_sdk /home/orangepi/robot_encrypted/stepper_motor_sdk
```

最终加密目录结构：

```
robot_encrypted/
  run_server.py                     # 明文启动器
  pyarmor_runtime_000000/           # PyArmor 运行时
  robot_control/                    # 加密后的源码
  motor_sdk/                        # 电机 SDK
  stepper_motor_sdk/                # 升降台 SDK
```

## 第四步：安装 Systemd 服务

### 控制面板服务

创建 `/etc/systemd/system/robot_control_panel.service`：

```ini
[Unit]
Description=Robot Control Panel (Encrypted)
After=network.target

[Service]
Type=simple
User=orangepi
WorkingDirectory=/home/orangepi/robot_encrypted
ExecStart=/usr/bin/python3 /home/orangepi/robot_encrypted/run_server.py
Restart=always
RestartSec=5
StandardOutput=append:/var/log/robot_control_panel.log
StandardError=append:/var/log/robot_control_panel.log

[Install]
WantedBy=multi-user.target
```

启用并启动：

```bash
echo orangepi | sudo -S systemctl daemon-reload
echo orangepi | sudo -S systemctl enable robot_control_panel.service
echo orangepi | sudo -S systemctl start robot_control_panel.service
```

### WiFi 热点服务（选配）

创建 `/etc/systemd/system/pipe_ap.service`：

```ini
[Unit]
Description=PipeRobot WiFi Hotspot
After=network.target

[Service]
Type=simple
ExecStart=/usr/bin/create_ap -n --no-virt --isolate-clients -w 2 --freq-band 2.4 wlan0 PipeRobot pipemaker
ExecStop=/usr/bin/create_ap --stop wlan0
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

> **注意**：开启热点后 Orange Pi 自身无法通过 WiFi 上网（单网卡限制）。需要远程访问时请关闭热点并连回外部 WiFi。

## 常见问题排查

### 网站显示"未连接"

1. 确认连接了正确的 WiFi（热点模式 `PipeRobot` 或局域网 IP）
2. SSH 登录：`ssh orangepi@<机器人IP>`，密码 `orangepi`
3. 重启服务：`echo orangepi | sudo -S systemctl restart robot_control_panel`
4. 详见过 `guide/troubleshooting.md`

### 摄像头无画面

1. 确认 USB 摄像头已插入 Orange Pi
2. 检查设备：`ls /dev/video*`（应看到 `/dev/video1`）
3. 检查 USB：`lsusb`（应看到摄像头设备）
4. 确认 ffmpeg 已安装：`which ffmpeg`
5. 摄像头模块支持热插拔，插入后自动检测，无需重启

### 电机不转 / GPIO 报错

- 检查日志：`grep -i motor /var/log/robot_control_panel.log`
- 预期看到：`Motor] Controller started — differential drive ready`
- 如果报 `motor_sdk not available`：检查 `robot_encrypted/motor_sdk/` 是否存在
- GPIO 引脚：左轮 IN1=29, IN2=31；右轮 IN1=35, IN2=37

### 升降台不工作

- 检查 `python-can` 是否安装：`python3 -c "import can; print(can.__version__)"`
- 如果报 `No such device`：CAN 总线硬件未连接（正常情况）
- 如果报 `No module named 'stepper_motor_sdk'`：检查 SDK 是否复制到 `robot_encrypted/stepper_motor_sdk/`

### PyArmor 加密报错

- `undefined symbol: _PyFloat_Pack8`：Python 版本不匹配。加密时的 Python 版本必须和运行时的版本一致（都是 3.12）
- 加密文件必须在目标机器上生成，不能跨设备复用不同 Python 版本的加密产物
- 加密文件生成后，复制回 PC 本地备份，避免重新部署时丢失

### 查看实时日志

```bash
tail -f /var/log/robot_control_panel.log
```

# 管道机器人 Mini 部署流程

## 设备信息

| 项目 | 值 |
|------|-----|
| 设备 | Orange Pi Zero 2W (aarch64) |
| 系统 | Ubuntu 24.04 Noble (Orange Pi 1.0.4) |
| Python | 3.12.3 |
| SSH 别名 | `pr_mini` |
| SSH 连接 | `frp-all.com:35000` / `orangepi` / `orangepi` |
| 工作目录 | `/home/orangepi/pr_mini/` |

## 一、SSH 配置

`~/.ssh/config` 中必须包含 `# password:` 注释元数据，ssh-skill 脚本依赖它：

```
# ===== pr_mini =====
# description: 管道机器人 Mini
# password: orangepi
Host pr_mini
    HostName frp-all.com
    User orangepi
    Port 35000
```

## 二、PyArmor 加密（Python 版本必须匹配）

**核心原则**：加密机器的 Python 版本 + 目标平台架构 = Mini 的 Python 版本 + 架构。

| | Python | 架构 |
|---|---|---|
| 本地加密机 | 3.12.13 (conda `robot_enc`) | Windows x86_64 |
| Mini 目标 | 3.12.3 | Linux aarch64 |

**本地加密命令**：

```bash
# 1. 创建 Python 3.12 加密环境（一次性）
conda create -n robot_enc python=3.12 -y
conda run -n robot_enc pip install pyarmor

# 2. 加密（每次源码更新后执行）
cd code/
conda run -n robot_enc pyarmor gen --recursive \
    --platform linux.aarch64 \
    --exclude "__pycache__" --exclude "*.db" \
    -O robot_encrypted robot_control/

# 3. 补充 web 静态资源（templates/static/ 不会被加密工具复制）
cp -r robot_control/web_gui/templates robot_encrypted/robot_control/web_gui/
cp -r robot_control/web_gui/static robot_encrypted/robot_control/web_gui/

# 4. 补充辅助文件（手动维护）
cp run_server.py robot_encrypted/
cp -r systemd/ robot_encrypted/systemd/
```

**为什么不能跨 Python 版本**：

PyArmor 的 `pyarmor_runtime.so` 是编译的 C 扩展，绑定到加密时的 Python C API。Python 3.10 加密的 runtime 在 3.12 上报 `undefined symbol: _PyFloat_Pack8`。

`--platform linux.aarch64` 解决 x86_64 → ARM64 的跨架构问题。

## 三、上传部署

**推荐方式：tar.gz 打包上传**（避免递归上传因中文路径 / 文件数量多而失败）

```bash
# 1. 本地打包（在 robot_encrypted 目录下）
cd D:/12_Projects/.../code/robot_encrypted/
tar -czf /tmp/pr_mini_deploy.tar.gz robot_control pyarmor_runtime_000000 run_server.py

# 2. motor_sdk 单独打包
cd D:/12_Projects/.../code/
tar -czf /tmp/motor_sdk.tar.gz motor_sdk

# 3. 创建干净目录 + 修复权限
python ~/.claude/skills/ssh-skill/scripts/ssh_execute.py pr_mini \
    "echo orangepi | sudo -S bash -c 'rm -rf /home/orangepi/pr_mini/*; mkdir -p /home/orangepi/pr_mini; chown -R orangepi:orangepi /home/orangepi/pr_mini'" --no-daemon --timeout 10

# 4. 上传 tar.gz（注意：Windows 下 /tmp 映射到 %LOCALAPPDATA%/Temp）
#    先用 cygpath -w /tmp/xxx.tar.gz 获取 Windows 路径
MSYS_NO_PATHCONV=1 python ~/.claude/skills/ssh-skill/scripts/ssh_upload.py pr_mini \
    "C:/Users/.../AppData/Local/Temp/pr_mini_deploy.tar.gz" \
    "/home/orangepi/pr_mini/deploy.tar.gz"
MSYS_NO_PATHCONV=1 python ~/.claude/skills/ssh-skill/scripts/ssh_upload.py pr_mini \
    "C:/Users/.../AppData/Local/Temp/motor_sdk.tar.gz" \
    "/home/orangepi/pr_mini/motor_sdk.tar.gz"

# 5. 解压 + 清理
python ~/.claude/skills/ssh-skill/scripts/ssh_execute.py pr_mini \
    "cd /home/orangepi/pr_mini && tar -xzf deploy.tar.gz && tar -xzf motor_sdk.tar.gz && rm *.tar.gz" --no-daemon --timeout 10
```

> **为什么不用 `--recursive` 逐个上传？** `ssh_upload.py --recursive` 遇到包含中文的路径时会报 `[Errno 2] No such file`，即使使用 `MSYS_NO_PATHCONV=1` 也无法解决。打包成单个 tar.gz 后再上传一次成功。

> **为什么需要 `chown`？** 上一步 `mkdir` 如果通过 `sudo` 执行，目录属主会变成 root，导致后续 SFTP 上传报 `Permission denied`。

**备选：逐个文件上传**（仅当路径不含中文且文件较少时可用）

```bash
MSYS_NO_PATHCONV=1 python ~/.claude/skills/ssh-skill/scripts/ssh_upload.py pr_mini \
    "D:/12_Projects/.../code/robot_encrypted/robot_control" \
    "/home/orangepi/pr_mini/robot_control" --recursive
# ... 其余文件同理
```

**注意**：`robot_encrypted` 目录的内容直接写入 `/home/orangepi/pr_mini/`，不保留外层 `robot_encrypted/` 目录名。`run_server.py` 自动检测项目根目录，无需修改路径。

## 四、依赖安装

### 系统依赖

```bash
# ⚠️ wiringpi 被 Orange Pi 镜像 hold，不能和 ffmpeg 一起装，必须分开
echo orangepi | sudo -S apt install -y ffmpeg python3-pip
```

> **为什么不能加 wiringpi？** Orange Pi 用 `apt-mark hold wiringpi` 锁定了 wiringpi 包，防止 Ubuntu 的 v2.50 覆盖 Orange Pi 专用版。如果和 ffmpeg 一起 `apt install`，整个事务会因 `--allow-change-held-packages` 缺失而失败。

> **apt 锁冲突**：系统首次启动后 `unattended-upgrades` 可能占用 apt 锁。如果遇到 `Could not get lock`，先 `sudo kill -9` 清理 apt 进程，再 `sudo rm -f /var/lib/apt/lists/lock /var/lib/dpkg/lock-frontend`。

- `ffmpeg` — 摄像头 MJPEG 流采集
- `python3-pip` — Python 包管理器（Orange Pi 镜像可能预装）

### wiringOP 编译（关键！）

**Ubuntu 的 `wiringpi` 包（v2.50）只支持树莓派，不支持 Orange Pi。** 系统自带 Orange Pi 专用的 wiringOP v2.56 源码，必须编译安装：

```bash
echo orangepi | sudo -S bash -c 'cd /usr/src/wiringOP && ./build clean && ./build'
```

编译后 `/usr/local/bin/gpio`（v2.46）会覆盖 Ubuntu 的 `/usr/bin/gpio`（v2.50）。验证：

```bash
gpio -v
# 预期输出包含: *--> OrangePi Zero2 W
```

### gpio sudoers 配置

电机控制需要 sudo 权限操作 GPIO：

```bash
echo orangepi | sudo -S bash -c 'echo "orangepi ALL=(ALL) NOPASSWD: /usr/local/bin/gpio" > /etc/sudoers.d/orangepi-gpio && chmod 440 /etc/sudoers.d/orangepi-gpio'
```

### Python 依赖

```bash
python3 -m pip install --break-system-packages \
    'flask>=3.0.0' 'flask-socketio>=5.3.6' \
    'python-socketio>=5.11.0' 'python-engineio>=4.9.0'
```

**踩坑**：Orange Pi 系统镜像使用华为 apt 源，`python3-setuptools` 包在镜像上 404。不要跟 apt 较劲——直接用 `pip3`（`/home/orangepi/.local/bin/` 下的 pip 不在 PATH 里，用 `python3 -m pip` 命令即可）。

`motor_sdk` 是本地包，使用 wiringOP `gpio` CLI 控制 GPIO，无 Python 依赖，无需 pip install。`robot_control/motor.py` 会在启动时将 `motor_sdk/` 目录加入 sys.path。

## 五、systemd 服务

### robot_control_panel.service — 机器人 Web 控制面板

**必须包含 `Environment=PATH=`**，否则 ffmpeg 找不到（systemd 默认 PATH 不含 `/usr/bin`）：

```ini
[Unit]
Description=Robot Control Panel (Encrypted)
After=network.target

[Service]
Type=simple
User=orangepi
```

### 移动端 WebSocket 修复

**现象**：Windows 浏览器打开 Web GUI 正常，手机浏览器显示「未连接」。

**原因**：`app.js` 中 SocketIO 只允许 `transports: ["websocket"]`。移动端浏览器或运营商网络可能阻止 WebSocket 握手，且没有 HTTP polling 回退，导致永远连不上。

**修复**（`robot_control/web_gui/static/app.js` 第 26 行）：

```diff
- const socket = io({ transports: ["websocket"], query: { lang: I18n._lang } });
+ const socket = io({ transports: ["websocket", "polling"], query: { lang: I18n._lang } });
```

加上 `polling` 后，WebSocket 失败时自动降级到 HTTP 长轮询。静态文件，上传后刷新即生效，无需重启服务。

## 十、关键坑位总结

| 坑 | 原因 | 解法                                            |
|----|------|-----------------------------------------------|
| PyArmor 加密后 Mini 上 import 报 `undefined symbol` | 本地 Python 3.10 加密的 runtime 用到 3.10 C API | 本地升级到 Python 3.12 再加密                         |
| `--platform` 不能少 | 本地 Windows x86_64, Mini Linux arm64 | `pyarmor gen --platform linux.aarch64`        |
| apt 华为镜像 404 | `python3-setuptools` 包缺失 | 放弃 apt，用 `pip3`                               |
| `pip` 命令找不到 | pip 装在 `/home/orangepi/.local/bin/`，不在 PATH | 用 `python3 -m pip`                            |
| sudo 密码管道串联失败 | 多个 sudo 串接时密码验证混乱 | 分步执行，关键操作先写 /tmp 再 sudo cp                    |
| `systemctl start` 报 `inactive` | 可能旧进程占用端口 | 先 pkill 再 start                               |
| **ffmpeg 未找到 (No such file)** | systemd 服务默认 PATH 不含 `/usr/bin` | service 文件加 `Environment=PATH=...`            |
| **电机控制离线** | `motor_sdk` 未上传 | 上传 `motor_sdk/` 目录到 Mini                      |
| **松开按键电机继续转** | app.js 每 50ms 重复发送命令，keyup 丢失后失控 | 简化为按住发一次、松开发 stop，不重复                         |
| **gpio 报 "Unable to determine board revision"** | Ubuntu `wiringpi` 包（v2.50）只认树莓派 | 编译 `/usr/src/wiringOP/`（v2.56 Orange Pi 版）    |
| **电机 mock mode / gpio mode failed** | gpio 二进制不对 + sudoers 未配置 | 编译 Orange Pi 版 wiringOP + 配置 NOPASSWD sudoers |
| **热点开启后 FRP 断开** | create_ap 独占 wlan0，机器人断网 | 正常行为——热点模式下通过直连 10.42.0.1:6080 访问              |
| **ssh_upload --recursive 全部 [Errno 2]** | 路径含中文（如 `机器人系统`）导致文件读取失败 | 用 tar.gz 打包成单个文件再上传                         |
| **SFTP 上传 Permission denied** | `sudo mkdir` 创建的目录属主为 root，orangepi 无写权限 | `sudo chown -R orangepi:orangepi /home/orangepi/pr_mini` |
| **ssh_execute sudo 管道被切后台失败** | 长超时触发后台模式，后台 sudo 管道执行失败 | 加 `--no-daemon` 且用 `bash -c '...'` 包裹命令       |
| **wiringpi 被 hold 导致 apt install 整体失败** | Orange Pi 镜像 hold 了 wiringpi 防止被 Ubuntu 包覆盖 | 分开安装：`apt install -y ffmpeg python3-pip`（不含 wiringpi） |
| **apt 被自动更新进程锁住** | 系统首次启动后 unattended-upgrades 自动运行 | `kill -9` 清理进程 + `rm -f /var/lib/apt/lists/lock` 后重试 |

# Revo 2 灵巧手通信协议设计 [​](#revo-2-灵巧手通信协议设计)

Revo 2 进阶版灵巧手支持 3 种对外通信接口：RS485、CAN FD和 EtherCAT（[点击此处了解EC协议说明](./EtherCAT.html)）。设计一套兼容485和 CAN FD通信接口的协议，在兼容不同通信协议的基础上确保通信的高效性、可靠性和易扩展性。

## **通信接口特点** [​](#通信接口特点)

### **RS485 特点** [​](#rs485-特点)

* **通信速率**：可达 10 Mbps，常用速率为 9600 bps~1 Mbps。
* **帧长**：支持不定长帧，帧最大长度受具体应用约束。
* **校验方式**：需软件实现 CRC16或者checksum 等校验方式，适应复杂电磁环境。
* **通信模式**：半双工通信，需要冲突检测机制。
* **可靠性**：抗干扰能力强，适合长距离通信。

### **CAN FD 特点** [​](#can-fd-特点)

* **通信速率**：数据段速率可达 5 Mbps，头部保持传统 CAN 速率。
* **帧长**：最大支持 64 字节数据段，扩展了 CAN 的数据载荷能力。
* **校验方式**：硬件内置校验，无需软件实现。
* **通信模式**：兼容传统 CAN 通信设备。

## 兼容性协议设计 [​](#兼容性协议设计)

Modbus-RTU 协议是一种主从请求应答通讯协议，广泛应用于工业自动化系统中。协议帧包括了地址、功能码、数据域、和 CRC 校验，以确保通信的可靠性。

**数据帧格式**：

| Header/Device ID | Function Code | Data | CRC16 |
| --- | --- | --- | --- |
| 1byte | 1byte | n bytes | 2 Bytes |

**Header/Device ID**: 设备标识符，用于区分不同的设备。

**Function Code**: 功能码，指示请求的操作类型。

**Data**: 数据域，包含具体操作的数据。

**CRC16**: CRC 校验，用于校验数据的完整性。

**RS485兼容 Modbus RTU：**

RS485本身不定义具体的通信协议，但通常与 Modbus RTU协议搭配使用，广泛用于工业自动化和监控系统中的数据传输。

**CANFD 兼容 Modbus RTU：**

CANFD 采用拓展帧，仲裁帧波特率固定位1Mb可将 CAN FD协议中的数据字段中帧ID包含Device ID和master ID还有数据长度，数据字段包含整个 Modbus RTU格式；

主机发送帧：

| CAN FD ID（29bit） | 数据段 (≤64Bytes） |  |  |  |
| --- | --- | --- | --- | --- |
| 24~28bit 0b00000 16~23bit Device ID 8~15bit Master ID 0 ~7bit Payload len | Header/Device ID | Function Code | Data | CRC16 |

设备应答帧

| CAN FD ID（29bit） | 数据段 (≤64Bytes） |  |  |  |
| --- | --- | --- | --- | --- |
| 24~28bit 0b00000 16~23bit Device ID 8~15bit Master ID 0 ~7bit Payload len | Header/Device ID | Function Code | Data | CRC16 |

## 功能码 [​](#功能码)

功能码用于标识请求的操作类型，每个功能码对应特定的操作，主要用于从设备中读取数据、写入数据或执行其他控制任务 ：

| 06H | 写单个保持寄存器 |

=== guide/两轴云台平衡原理.md ===

工作。依据刚体定轴转动的动量矩定理得：
$$\frac{dJ_{\alpha}}{dt}=M_{\alpha}$$
式中：$\alpha$ 为转动角加速度。
动能定理：
$$
dT = dA$$
定轴转动动能定理：
$$\frac{1}{2}Jw^2 = \frac{1}{2}J_dw^2 + \frac{1}{2}J_Lw^2$$
式中：$J_d$ 为电机转动惯量；$J_L$ 为负载转动惯量。
由式（1）~（3）得出云台总动能 $T$：
$$
T = \frac{1}{2}J_{z_1}^2 + \frac{1}{2}J_{i_2}\beta^2 + \frac{1}{2}J_{i_2}\cos^2\beta + \frac{1}{2}J_{i_3}(\beta\cos\gamma + \cos\beta\sin\gamma)^2 + \frac{1}{2}J_{z_3}(\cos\beta\cos\gamma - \beta\sin\gamma)^2$$
式中：$J_z$、$J_y$ 分别为横滚轴、俯仰轴定轴转动惯量；$\beta$、$\gamma$ 分别为横滚轴、俯仰轴定轴转动角度。
由拉格朗日方程可得两个转动轴电机转动力矩：
$$\frac{d}{dt}\left(\frac{\partial T}{\partial\beta}\right) - \frac{\partial T}{\partial\beta} = M_1$$
$$
\frac{d}{dt}\left(\frac{\partial T}{\partial\gamma}\right) - \frac{\partial T}{\partial\gamma} = M_2$$
将式（5）~（6）代入式（4）中得出云台稳定方程：
$$(J_{Y_2} + J_{Z_3})\beta + (J_{Z_2} + J_{Z_3})\sin^2\beta = M_1$$
$$
J_{z_3}(\gamma - \sin\beta - \beta\cos\beta) = M_2$$
从以上公式可得：当云台运转时通过改变电机的转动惯量来使云台的总能量 $T$ 保持不变，进而实现云台的稳定。

姿态解算俄版云台的姿态解算主要分为：1）原始数据低通滤波2）互补滤波计算姿态角(方位角)3）四元数计算姿态角(航姿角)云台中使用了两种方法计算姿态角，一种是互补滤波，一种是四元数，互补滤波的权重系数由于是固定的，因此不会发散，在云台中也一直计算，作为一个显示对比数据，通过四元数计算的姿态角加入了运动中的影响，估计的姿态角作为控制层的反馈状态。使用两种方法在实际出问题时，做数据对比。互补滤波计算方位角互补滤波中计算方位角时，由于是直接使用转换为欧拉角进行计算，因此需要在融合陀螺仪的角速度数据时，需要区分欧拉角速度与机体角速度的区别，它们之间有转换矩阵需要进行转换。欧拉角速度与机体角速度是不同的欧拉角是相对地面而言的，对欧拉角求导的欧拉角速度也是相对地面的。而机体角速度是相对机体本身的，也就是相对于IMU的原点位置。当机体系与地面坐标系本身就有一定的偏差时，两者差异就会比较大，因此需要一个转换矩阵。互补滤波得到俯仰角与横滚角陀螺仪直接测量到的角速度是机体角速度，在转换为欧拉角速度后，乘以时间间隔，再加上上次的估计值，就得到一个陀螺仪积分计算的角度，作为预测值。加速度计测量到的加速度值可以计算出pitch与roll，作为测量值。在云台中，陀螺仪的角速度是短期可靠的，加速度计容易受到振动的影响，在长期是可靠的，互补滤波就是给陀螺仪积分得到的角度与加速度计得到的角度分别给权重，利用测量值(加速度计测量得到的角度)校正预测值(陀螺仪积分得到的角度)。在云台中，权重给的比较简单：orient[PITCH]   = (orient[PITCH] + gyroRate[PITCH] * dt) + 0.0002f * (smoothAcc[PITCH] - orient[PITCH]);
航向角融合在方位角的估计中，直接使用欧拉航向角速度进行积分得到航向角。四元数计算航姿角与方位角的估算不同的是，使用四元数计算航姿角引入了两个概念来达到校正的目的：1）使用重力分量作为参考量计算角速度积分得到的姿态与加速度计得到的姿态之间的误差2）使用PI控制器消除误差大致流程如下：1.使用角速度以及龙格库塔积分更新四元数q0i = (-q1 * gx - q2 * gy - q3 * gz) * halfT;
q1i = (q0 * gx + q2 * gz - q3 * gy) * halfT;
q2i = (q0 * gy - q1 * gz + q3 * gx) * halfT;
q3i = (q0 * gz + q1 * gy - q2 * gx) * halfT;
q0 += q0i;
q1 += q1i;
q2 += q2i;
q3 += q3i;其中 gx，gy，gz 是机体坐标系下的融合角速度2.将当前四元数转化为方向余弦矩阵(机体坐标系)并提取出重力分量，得到在机体坐标系下角速度积分得到的姿态(四元数可以看作是经过加速度计修正的角速度积分得到的位姿)中的重力分量向量vg重力加速度向量是以 [0，0，-g]，在云台中，进行了归一化处理，也就是重力加速度向量为 [0,0,-1]，因此在俄版云台中，得到角速度积分的位姿的重力分量的实现为：vx = 2.0f * (q1q3 - q0q2);//计算方向余弦矩阵
vy = 2.0f * (q0q1 + q2q3);
vz = q0q0 - q1q1 - q2q2 + q3q3;3.加速度计就是实测出来的在机体坐标系下的重力加速度，归一化后作为重力向量的测量值 ag ，但由于可能处于运动状态，此时就不单单是重力加速度了，因此计算了一个可信度参数，叠加到 Kp 参数上calculateAccConfidence(norm);//由于处于运动状态，所有要计算加速度数据归一化后的可信度
kpAcc = eepromConfig.KpAcc * accConfidence; //加速度比例系数 * 可信度
kiAcc = eepromConfig.KiAcc * accConfidence;//加速度积分系数 * 可信度
normR = 1.0f / norm; //加速度归一化
ax *= normR;
ay *= normR;
az *= normR;4.计算 vg 与 ag 的叉积，得到两者的偏差向量，可以理解为通过积分得到的姿态与加速度计得到的姿态的角度偏差exAcc = vy * az - vz * ay; 
eyAcc = vz * ax - vx * az;
ezAcc = vx * ay - vy * ax;5.偏差经过 Kp，相当于是互补滤波中的加速度计计算的角度的权重，第4步计算出来的叉积，相当于是向量 vg，绕某轴，旋转n度，就可以旋转到向量 ag ，向量 vg 相当于是通过角速度积分得到的角度，向量 ag 相当于是加速度计测量得到的角度，如果 Kp = 0，那么相当于不旋转，以 vg 向量为准，如果 Kp 比较大，那相当于旋转的角度比较大，以 ag 为准。gx += exAcc * kpAcc;//比例增益控制加速度计的收敛速度
gy += eyAcc * kpAcc;
gz += ezAcc * kpAcc;同时，也增加了积分项，逐步消除两种测量方式之间的误差：exAccInt += exAcc * kiAcc;
eyAccInt += eyAcc * kiAcc;
ezAccInt += ezAcc * kiAcc;
gx += exAccInt;
gy += eyAccInt;
gz += ezAccInt;上述相当于是，角度误差->PI控制器->校正角速度。也就是 gx，gy，gz 就是校正角速度。6.将校正角速度代入四元数，更新四元数    q0i = (-q1 * gx - q2 * gy - q3 * gz) * halfT;
    q1i = (q0 * gx + q2 * gz - q3 * gy) * halfT;
    q2i = (q0 * gy - q1 * gz + q3 * gx) * halfT;
    q3i = (q0 * gz + q1 * gy - q2 * gx) * halfT;
    q0 += q0i;
    q1 += q1i;
    q2 += q2i;
    q3 += q3i;
