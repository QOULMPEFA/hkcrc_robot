# v1.10 — UGV Bridge Deadlock Fix + TCP Framing + Sudo Password

**Date:** 2026-06-12 17:31

## Changes

### UGV Bridge (`ugv_bridge/ugv_bridge.cpp`)
- **Fix** Mutex deadlock: command processor no longer calls SDK directly — only updates tracking variables. Motion heartbeat (50Hz) is the sole caller of `SetMotionCommand`, eliminating "Resource deadlock avoided" crash
- **Fix** TCP line-oriented framing: added `rx_line_buf` accumulator + newline splitting — prevents "Unknown cmd" from partial/multi-line reads
- **Fix** `SetMotionMode` only called on actual mode change (spinning ↔ ackerman), reducing SDK contention
- **Fix** Enable handler calls `ResetRobotState()` before `EnableCommandedMode()` to clear fault 0x0200
- **Fix** Auto-enable on CAN connect (no longer "manual enable required")
- **New** Estop uses pending flag + heartbeat to avoid duplicate SDK calls

### Server (`robot_control/web_gui/server.py`)
- **Fix** Sudo password: shutdown/reboot changed from `orangepi` to `1114` (matches Jetson's actual sudo password)

## Root Cause: Bridge Deadlock
Calling `SetMotionCommand`/`SetMotionMode` in the command processor AND immediately after in the heartbeat (~20ms apart) caused the ugv_sdk's internal ASIO/thread to throw `std::system_error: Resource deadlock avoided`. Reducing to a single SDK call per loop iteration fixed it.

## Root Cause: Keyboard Failed
The bridge deadlock killed the process, severing the TCP connection. The Python UGV module would reconnect and auto-enable, but the next velocity command would trigger another deadlock → crash cycle. Fixing the deadlock restored continuous keyboard control.
